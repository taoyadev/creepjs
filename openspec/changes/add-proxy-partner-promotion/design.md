# CreepJS 合作代理商推广实施计划

状态：2026-10-29 已批准实施。以下记录批准的设计与验收要求；实施证据见 tasks.md 和 docs/PARTNER_ACCEPTANCE.md。任务状态以 [tasks.md](./tasks.md) 为准，行为验收以本目录 `specs/` 为准。

## 1 结果与范围

完成一条可使用、可解释、可衡量的推广路径：

`IP 检测结果 → 合作商介绍或选型指南 → 商家合作链接 → 商家确认成交 → 对账`

第一阶段交付四个主体：IP 结果推荐、合作商目录、首篇选型指南、第一方曝光与点击统计。网站继续以检测为主要任务，商业推荐不修改检测结论，不使用检测数据选人或选商家。

第一阶段使用现有 Next.js 静态导出、组件、第一方事件 API 和 OpenClaw 验证链。采用英文页面文案；不新增依赖、数据库、广告 SDK、招商后台、订单系统、重定向服务、个性化推荐或实验平台。

## 3 需要运营者提供的真实资料

实施前从对话和项目中先检查是否已有资料，再集中索取缺失项。先接一家即可；有两到三家差异明确的商家时再比较。不因缺资料编造品牌、价格、测试结论或购买链接。

| 输入           | 要求                                                            | 缺失时的处理                                         |
| -------------- | --------------------------------------------------------------- | ---------------------------------------------------- |
| 商家名称与官网 | 真实可核实；Logo 只有取得使用权限后才纳入本地静态资产           | 可只用文字品牌，无需 Logo                            |
| 合作链接       | 已分配给运营者的 HTTPS URL，确认最终商家和允许的渠道参数        | 可以开发组件；不发布虚构推广按钮                     |
| 产品与适用需求 | 类型、地区、协议、会话能力、计费单位、最低购买门槛、支持方式    | 未核实字段写明未披露，不能推断                       |
| 优惠或试用     | 权益、资格、限制、期限与官方条款链接                            | 没有权益就用“View plans”，不显示专属优惠承诺         |
| 合作结算       | 首单/续费、归因窗口、退款扣佣、结算周期、报表是否支持位置级渠道 | 留在既有私有业务渠道；不写入网页配置或公开仓库       |
| 目标市场       | 国内或海外，主要需求                                            | 未提供时沿用网站英文界面，不把英文误认为已知访客分布 |

可复制给运营者的资料格式：

```text
商家名称：
官网：
我的合作链接：
可用渠道参数及允许值规则：
主推产品与适合的需求：
限制或不适合的需求：
优惠或试用及条款链接：
资料来源和核实日期：
目标用户地区：
成交报表能区分哪些渠道：
```

佣金合同、商家后台凭证、客户订单、邮箱和 API 密钥不进入公开配置。浏览器最终要打开的联盟链接属于公开 URL；如果链接带的是后台访问凭证，应先更换为商家提供的公开推广链接。

## 4 页面与内容设计

### 4.1 IP 结果推荐

位置：`/ip` 完整结果中的证据列表和方法/时效说明之后、批量查询工作区之前。用户先读完检测内容，再看到推荐；最多两家卡片，不弹窗、不自动跳转。

展示条件是存在成功返回的结果及至少一家有效合作商。查询未开始、正在加载、输入无效、超额、取消、上游报错时不插入推荐。成功结果含 unknown 或风险标记时，可以显示同一份中性推荐；文案不能把缺数据解释为危险或必须购买。再次输入或重查不得改变已有检测逻辑。

推荐选择只使用审核后的固定编辑顺序与配置的展示位置。第一阶段不根据用户 IP、国家、ASN、风险分数、指纹、浏览记录或身份重新排序，也不加入运行时选型问卷。

建议英文文案：

```text
Explore proxy providers
Compare partner services for your network requirements.
Sponsored partnerships. We may earn a commission from qualifying purchases.

[Provider name]
[One verified use case]
[Proxy type · Billing unit · Important limitation]
[View plans]  [Compare providers]

Partnerships do not affect your IP check results.
```

商家卡片视觉层级低于检测结果和主要操作；合作标记与 CTA 相邻，不能只藏在页脚。未知字段和限制同样可见。推广内容不进入查询报告、复制 JSON、分享参数或批量导出。

### 4.2 合作商目录

公共路径固定为 `/proxy-providers`，页面标题为 `Proxy providers`。页面顺序：用途简介、合作披露、选择要点、商家资料卡/比较信息、资料核实说明、相关指南和检测入口。

每家展示品牌、已核实产品类型、适用需求、主要限制、计费方式、来源/核实日期、可用权益和一个主要外链 CTA。桌面可使用紧凑比较表，手机改为纵向卡片或有明确提示的局部横向区域；整页不得横向溢出。

只有一家时正常展示单家介绍，不造“Top 3”。没有有效商家时展示普通的暂无合作资料状态、返回工具和选型文章的入口；目录设 `noindex`，从导航和 sitemap 排除，不能作为已完成商业发布交付。

排序用明确编辑顺序。若未来出售优先位置，应标明赞助位并重新确认规则；当前不做评分、星级、匿名用户评价、虚构“最佳”排行或全行业覆盖声明。

### 4.3 导航与既有内容入口

- 共享导航增加 `Proxy providers`，目录有正确的 `aria-current`；Home、Checker、IP Risk 等现有入口继续可用。
- 在现有 `/ip-lookup/how-to-tell-if-an-ip-is-a-proxy` 解释内容之后增加选型指南和目录内链，避免在诊断结论中混入购买按钮。
- 第一阶段首页只通过共享导航提供入口；`/checker` 推广位留到后续，不扩大这次验收范围。
- 新导航使 768/1024px 宽度拥挤时，仅调整必要的导航断点或间距，保留移动菜单的焦点、Escape 和关闭行为。

### 4.4 首篇选型指南

固定路径 `/guide/static-vs-rotating-proxies`，建议标题 `Static vs rotating proxies`。正文回答：固定出口与轮换行为的区别、会话持续时间、如何按网络需求选择、计费单位与预算、测试地区/延迟/成功率的方法，以及代理不能直接改变浏览器 Canvas/字体指纹的边界。

明确“静态/轮换”描述出口或会话行为，“住宅/ISP/机房”描述产品或网络来源，不能将两个维度混成同一分类。协议、轮换行为、退款等具体事实在撰写时查商家官方资料。没有实际测试就不用“实测”标题。

文章先完整解释问题，再用一段相关合作商介绍连接目录；使用同一份商家资料，不复制容易漂移的价格表。提供返回 `/ip` 的检查入口。无虚构 Review/AggregateRating；沿用现有 metadata 与结构化数据工具。

## 5 资料、组件与公共读路径

### 5.1 一份审核后的公开资料源

建议新增 `apps/web/src/lib/proxy-providers.ts`。最小字段：稳定 `id`、`name`、`status`（active/paused）、`order`、`websiteUrl`、审核后的产品说明、适用需求、限制、`sources`、`verifiedAt` 和按位置配置的 `outboundUrls`。已知有真实权益时才加入可选权益内容和官方条款。

商家 ID 使用现有 slug 规则、最多 48 字符，创建后不改不复用。允许链接域名与真实合作链接一并审核；原始链接不可由 query string、用户输入或页面结果拼接。校验 HTTPS、无 URL 用户名密码、ID 唯一、日期有效、位置有效、active 商家具有必要链接及资料。

合法数据为空是受支持状态；配置中声明 active 却缺字段或含非法链接，应在构建/检查阶段报错，避免静默发布半成品。Logo 是可选的本地资源，不从商家服务器按访问量加载。

第一阶段不发布需要实时更新的价格数字或倒计时。需要提及价格时必须是明确日期的历史核实值并链接当前套餐。短期优惠只有在条款、有效期和到期前下架发布安排都确认后才可承诺；没有下架安排时只链接商家当前优惠，不写具体短期权益。已知过期权益不得继续用现在时承诺。商家退出时暂停资料并重新发布，保留商家 ID 的历史含义。

### 5.2 最小组件划分

可复用的卡片/披露展示与一层处理点击、可见曝光的 client 组件即可，不建立通用广告框架。目录和指南主体保留静态 HTML；浏览器仅负责曝光观察与第一方点击事件。

外链使用普通可访问的 `<a>`，`rel="sponsored noopener noreferrer"`，`referrerPolicy="no-referrer"`。选择新标签打开时明确告知；不依赖 JS 才能跳转。静态 href 只包含核实过的商家渠道参数；不传当前页面完整 URL，尤其是 `/ip?q=...`。

无 JS、统计请求失败、用户拒绝统计或商家最终页面不可达时，本站检测都不能受影响。用户点击前不预取商家页面、不加载商家脚本/像素、不把商家域名加入 preconnect。

### 5.3 公共读取成本

输入是运营者核实的配置；构建形成版本化静态 HTML/JS；Pages 按现有方式分发。发布者是现有受管发布流程，版本是该次来源提交与构建回执。

新增商业公共页面的每次读取预算：业务真相读取/写入 0、商家后台请求 0、生成/排序服务执行 0、通知 0。另行触发的第一方统计 POST 是有界遥测，沿用现有单条写入、不使用 KV/DO 的结构，不能混入公共 GET 的业务重建。

商家资料显示核实日期，作为已发布的资料快照；不声称实时价格或实时库存。运营者至少每 30 天复核一次，遇到合作终止、链接失效或产品变化即更新。失败发布保留上一完整版本，不能由访客请求触发“补抓取”。优惠必须满足其独立的时效条件，不能靠“资料快照”延长有效期。

## 6 曝光、点击与成交口径

### 6.1 事件契约

| 行为                 | 事件                                | props                                           | 计数口径                                                |
| -------------------- | ----------------------------------- | ----------------------------------------------- | ------------------------------------------------------- |
| 商家卡片进入可视区域 | 新增 `partner_impression`           | `label: providerId`、`section: placement`       | 单次页面生命周期中，同一商家/位置最多一次               |
| 商家外链由用户激活   | 复用 `link_clicked`                 | 同上                                            | 同一页面生命周期中，同一商家/位置最多一次；导航始终执行 |
| 导航进入目录         | 复用 `link_clicked`，可复用现有处理 | `label: proxy-providers`、`section: navigation` | 与商家成交点击分开统计                                  |

推广位置固定为 `partner-ip-result`、`partner-directory`、`partner-guide`。后续加位置只能追加，不重新解释旧值。`label` 的商家 ID 不用于传优惠码、URL 或自由文本。

`partner_impression` 在共享事件表声明必需的 `label/section`；不新增 props 或 Analytics Engine 列。现有 API schema 从共享表派生；优先补测试，只有实际发现兼容问题才改路由实现。

曝光采用 IntersectionObserver：卡片可见面积达到 50%，且文档处于可见状态时发送。未滚到卡片不计数。没有 IntersectionObserver 时跳过曝光，外链照常可用；不伪造“已曝光”。

去重只保存在当前页面生命周期内的内存集合，key 为商家 ID 和位置，保留在不会随 `/ip` 查询重渲染而丢失的父级。不得写 cookie、localStorage、sessionStorage 或生成访客 ID。离开后再次访问可以计为新页面实例；这不是独立用户数。

普通鼠标、键盘激活可统计；支持中键时处理一次 auxclick。右键复制链接或统计拦截导致的漏计属于已知限制。先确保普通外链导航，再尽力发送事件；不 `preventDefault` 等待统计。

### 6.2 商家侧归因

商家支持 subid 等渠道参数时，使用事先确认的固定位置值；URL 在配置中预先形成。商家只支持一个链接时，记录为商家级归因，不能声称可核对位置级订单。优惠码只能作为商家支持的补充证据，不能证明站内某个访客成交。

成交、退款和佣金以商家报表为依据。第一阶段使用其现有后台/导出进行人工对账，不实现 postback、订单导入或用户级跨站关联。确认商家自身的归因窗口和结算口径后才定义收入报表。

### 6.3 统计验收与指标

- 站内曝光/点击在同一可统计样本、商家和位置下比较；点击率是页面实例层面的近似值，不是独立用户转化率。
- 商家报表的已确认订单、退款和已结算佣金独立列示；不把站内点击直接标成成交。
- 每千次可观测曝光对应的结算收入只能作为方向性估算，标清跨系统漏计、不同归因窗口、DNT/GPC 和采样影响。不能当作审计级逐人漏斗。
- 既有 `tool_run` 可比较成功与错误事件占比，但缺少开始/取消分母，不能称为“所有用户的检测完成率”。查询体验同时依靠浏览器流程、请求次数和性能回归验收。
- 不预设无依据的 CTR、收入或订单承诺。发布后先收集一个完整商家归因/结算周期的基线；样本太少时不据此宣称某家胜出。

生产数据验证需要受授权的 Analytics Engine 查询或控制台证据：在明确时间窗内触发非购买的测试事件，查到对应事件名、商家 ID、位置和列布局。涉及采样时按当前官方查询口径处理，不能简单把返回行数当事件总数。不得为验证自动下单或伪造订单。

## 8 实施顺序与完成条件

### A 复核与边界确认

记录当前 Git 状态和 HEAD，读取积累规则及本计划。确认用户的实施指令是否已批准本提案与 `docs/ENDGAME.md`；已有明确授权就继续。收集缺失商家资料，先完成不依赖真实数据的工作。

退出条件：已确定文件基线和发布范围；未解决的商家/账号事项有明确记录，不误标为代码故障。

### B 商家资料和静态内容

建立公开配置、校验、静态目录与选型指南；增加导航和内链；保留无有效商家的真实状态。真实资料缺失时，开发可继续，但正向商家集成与商业发布不能验收完成。

退出条件：有真实商家时，目录 HTML 可直接读取，所有声明有依据；空名单和暂停商家均有正确行为；新 URL 与 metadata/路由表一致。

### C IP 推荐和事件

加入最多两张结果后推荐卡；建立内存去重和低基数事件；补前端/API 负面路径检查。统计与查询解耦，响应错误、DNT/GPC、无 JS 均不影响可用性。

退出条件：完整 IP 查询回归通过；可见性与去重规则可运行验证；链接和请求中无 IP/指纹/完整页面 URL；API 固定列保持兼容。

### D 预览验收

在 OpenClaw 对实际待交付快照完成格式、构建、类型、lint、测试与浏览器 QA。使用真实商家资料时只检查链接配置与页面，不执行注册、购买或对外联系。用受控 fixtures 验证失败状态并在证据中区分。

退出条件：验收矩阵有明确 pass/fail 和来源快照；相关失败修复后重新验证受影响项。预览通过不自动表示生产已上线或统计已存储。

### E 生产衡量和发布

仅在执行 session 有相应明确授权或既有发布路径授权时操作。账号启用或可能收费事项必须有对应授权；如果当前未授权，完成代码与预览并交付具体待办。

读取当前 release、生产账本和运行配置后确认部署顺序：API 支持新事件及授权后的绑定 → Web 使用该事件 → canonical 浏览器检查 → 数据存储查询验证。使用现有 `~/.codex/bin/release`，不绕过 protected workflows。

只有 Web 发布而 API 未更新时不能宣称推广统计完整。绑定未启用时保持现有 API 的降级行为，不能在新 session 擅自替换为 KV 写入、第三方像素或新服务。

## 11 发布、回退与后续运营

发布前：真实商家资料已核实、优惠无过期承诺、披露可见、统计路径经过相应级别验证、API 与 Web 顺序明确、预览完整通过。上线授权仅按用户明确指令或已有 ship route 判断。

运行问题可通过暂停对应商家并重新构建发布来移除推荐；保持既有检测功能。API 已支持的新事件可以保留，旧 Web 不依赖它。代码或部署回退使用已批准的版本发布路径，不重置用户工作区。

上线后每周按商家和位置核对曝光/点击及商家报表；至少每 30 天复核商家资料。首轮只调整已有文案、位置与排序，一次改变一个变量并记录时间，避免小样本宣称因果。只有得到足够可解释的数据或用户明确要求，才扩大到 `/checker`、更多文章、更多商家或其他合作形式。
