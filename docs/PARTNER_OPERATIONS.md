## 接入清单

运营者集中提供：名称、官网、公开 HTTPS 合作链接、允许的固定渠道参数、主推产品、地区、协议、会话规则、计费单位、最低购买门槛、支持方式、适合及不适合的需求、官方来源及核实日期。未公开的非关键产品字段明确填写 `Not disclosed`；不能据此推断承诺。

1. 创建不超过 48 字符的稳定小写 slug ID，遵循共享事件 slug 规则。改名不改 ID，停用不复用。
2. 核实官网、来源、合作链接及中间跳转域名，把精确 host 写入 `approvedHosts`。链接必须是无用户名密码的 HTTPS 公共推广 URL；人工确认它不是后台凭证。
3. `outboundUrls` 必须提供 `partner-directory`。仅为已确认渠道配置 `partner-ip-result` / `partner-guide`；缺某位置链接即不在该位置展示。一个商家级链接可以复用，但不能声称位置级订单归因。
4. 指定固定 `order`；推荐仅取此顺序前两家。未知风险、高风险、地区、ASN 或指纹都不会改排序。
5. 运行配置测试与完整 OpenClaw 检查，预览实际内容、最终目标和披露。测试用 `.test` 商家只用于隔离验收，不能复制为 active 公开资料。
6. 至少每 30 天复核，合作终止或链接/产品变化时立即暂停或更正，再通过受管流程发布。暂停保留 `{ id, status: 'paused' }` 墓碑。

当前 CTA 统一为 `View plans`，不承诺优惠。若后续提供具体优惠，先核实资格、官方条款、期限和到期前下架发布安排，再增补受测字段和展示；当前不能把短期优惠硬编码在描述里。Logo 非必需，本阶段使用文字品牌。

## 站内统计

| 项目         | 口径                                                                                                            |
| ------------ | --------------------------------------------------------------------------------------------------------------- |
| 曝光         | `partner_impression`；至少 50% 卡片可见、文档可见；页面实例内同商家/位置一次                                    |
| 商家外链激活 | `link_clicked`；`label=稳定商家ID`，`section=partner-ip-result/partner-directory/partner-guide`；页面实例内一次 |
| 目录导航     | `link_clicked`；`label=proxy-providers`，`section=navigation`；与商家点击分开                                   |
| 存储列       | `blobs=[name,path,tool,surface,outcome,status,section,label]`，`indexes=[name]`，`doubles=[1]`                  |
| 隐私         | 不传查询参数、IP、指纹、分数、用户标识、优惠码或完整 URL；DNT/GPC 不发送                                        |

去重只在内存中，页面卸载后重建。没有 IntersectionObserver 时不计曝光。统计拦截、离页传输失败、右键复制、浏览器恢复方式都可能影响计数；普通/键盘激活与中键尝试发送事件，不等待统计，不阻断导航。这些数值不是独立用户数。

站内可观测点击率 = 同时间窗、同商家、同位置的激活数 / 曝光数，只是页面实例近似指标。曝光因视口高度等原因漏计时，点击与曝光不一定构成严格漏斗；不要修补成虚构数据。

## 成交、退款与结算

在商家私有报表中确认归因窗口、首单/续费、时区、币种、退款扣佣、结算周期和支持的渠道粒度，再开始记录。站内不导入订单、不建立 postback、不匹配个人。

每周人工核对一次，首轮至少覆盖一个完整归因及结算周期。对账记录包含：统计起止时间与时区、商家 ID、可用的位置渠道、站内可观测曝光/激活、商家已确认订单、退款、结算币种与已结算佣金、来源报表日期、归因窗口、待确认差异。没有真实报表时留空并写“未提供”，不要填 0 暗示实际查询过。

商家只给总渠道报表时只能核对商家级结果。点击不能记成订单，优惠码不能证明某位本站访客成交；跨系统漏计、采样、归因窗口、退款延迟均单独解释。每千次可观测曝光收入只作方向性估算，不是逐人审计结果。

## 存储与发布条件

1. 账号服务启用及可能收费的动作需要对应授权。继续使用现有 Analytics Engine 方案；不擅自增加 KV、数据库或第三方像素。
2. 授权启用后恢复 Worker 的 `EVENTS` → `creepjs_events` 绑定，先发布 API，再发布 Web。`.codex/release.json` 使用 `deploy-direct.sh all`；手动 dispatch 串行等待，push 的 Web 生产步骤在共享契约变化时等待同 SHA 的 API 生产工作流成功。现有检查与保护继续生效。
3. 先合流最新生产基线（本次发布分支已整合至 PR #22，含 IP 首帧、可读性、隐私和发布链修复），保留推广改动并重跑完整 release gate。再用受管 `~/.codex/bin/release run --go` 发布，不能以当前脏工作区绕过提交与保护。发布后验证 canonical 页面和真实商家外链。
4. 在明确 UTC 时间窗发送非购买测试事件，以已授权查询查出事件、位置、商家及固定列；没有存储查询证据不能标为统计已启用。若 Analytics Engine 采样，应按当时官方 SQL 查询规则使用采样权重；不要将原始行数当总事件数。
5. 分别记录代码、预览、商家核实、生产版本、存储入库、商家报表六项状态。商业发布需要真实商家；预览通过不替代这些条件。

公共内容由构建快照生成，访问目录/指南不读取商家后台、不重排业务排名、不生成通知或写业务真相。独立事件 POST 复用原有单点写入预算，不触碰 KV/DO。发布失败保留上一完整版本，访客请求不负责补抓取。
