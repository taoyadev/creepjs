# CreepJS 产品边界

状态：本次合作代理推广边界已获用户批准实施（2026-10-29）。当前交付范围是可审查代码和 OpenClaw 预览证据；生产及账号服务状态分别记录。

## 产品结果

CreepJS.org 提供可解释的浏览器指纹与 IP 检测、相关知识内容、开发者 API 与 SDK。检测结果帮助用户理解观察值、缺失数据与局限；检测结论不受商业合作影响。

本次新增的已知需求是在网站推广运营者合作的 IP 代理服务商。用户可以完成检测、比较服务、阅读选型说明，并自主前往商家购买。网站通过公开说明的合作链接获得商业回报，成交与结算由商家体系确认。

## 本次确定的长期边界

- 检测输入、IP、指纹、风险分数和报告不用于广告画像，不传入推广链接或商家统计。
- 商家推荐采用人工核实的公开资料与明确适用场景；付费位置标明合作关系，不出售检测分数、白名单或“安全认证”。
- 站内统计只保留现有事件结构支持的低基数字段，尊重 DNT/GPC；不建立用户级成交追踪或持久广告 ID。
- 商家名录和选型文章是构建时发布的静态内容。公共访问不查询商家后台、不拉取实时价格、不重算排名、不触发业务写入或通知。
- 站内商业内容与网站界面保持英文；本次规划和交接文档用中文。
- CreepJS.org 与 Abraham Juliot 的 CreepJS 研究项目的现有区分继续明确，合作不暗示获得后者背书。

## 一次确定的公共契约

| 契约           | 决定                                                                                               | 迁移或破坏性影响                                                 |
| -------------- | -------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| 合作商目录     | `/proxy-providers`，目录内以稳定商家 ID 作锚点                                                     | 新增 URL，不修改现有 URL，无已有内容迁移                         |
| 首篇选型指南   | `/guide/static-vs-rotating-proxies`                                                                | 新增 URL，无重定向或旧内容迁移                                   |

| 商家资料所有权 | 运营者维护仓库中的审核后公开资料；凭证、佣金合同与订单留在既有私有业务渠道                         | 不建立新数据库或导入私人订单                                     |
| 事件数据       | 复用 `label` 表示商家 ID、`section` 表示展示位置；新增 `partner_impression` 事件                   | 只增事件名，不改现有列顺序、字段含义或历史记录                   |
| 商家跳转       | 直接使用核实过的 HTTPS 合作链接                                                                    | 不新增 `/go` 重定向服务或站内结账协议                            |
| 侧边赞助位     | 桌面 1440px+ 全站左右侧栏，共 8 位，最后一位固定为 “Advertise here”；`section=partner-sidebar`     | 只增位置值，复用既有事件列；手机端不显示                         |
| 广告留资       | `POST /v1/sponsor-inquiries`，仅站点来源；邮箱 + 可选网址存独立 KV `SPONSOR_INQUIRIES`，180 天过期 | 新增接口与命名空间；未绑定时返回 503，网页给出 hello@creepjs.org |

这组变更不需要迁移已填充数据，也不破坏既有公共 URL、API 响应或 SDK 契约。若实施中需要用户级 ID、订单回调、数据库、商家自助后台或可变跳转端点，应先修订本文件和提案，不能把它们当作本计划的隐含要求。

## 本次交付边界

第一阶段包含：IP 结果后的推荐模块、合作商目录、共享导航入口、一篇选型指南、相关既有教程的内链、曝光和点击统计、披露与验收。

`/checker` 网络区域推广、更多商家文章、更多语言、自助结账、自动佣金结算、动态竞价与推荐算法均不属于第一阶段。只有确认需求和效果后才另行设计。

2026-10-31 用户要求增加：参照 TrustMRR 的对称侧边赞助位，以及只收邮箱的广告咨询弹窗（无价格、无在线支付、无站内后台；运营者用 Wrangler 读取咨询记录）。创建 `SPONSOR_INQUIRIES` 命名空间和生产发布各需单独授权。

当前 [PRD](./PRD.md) 禁止为广告追踪用户，仍然成立。[LAUNCH_PLAN](./LAUNCH_PLAN.md) 中旧的“no ad/tracking”概括需在实施时明确为：允许公开披露的静态合作推荐，继续禁止基于检测数据的广告追踪。此次边界确认不自动启用生产账号服务。
